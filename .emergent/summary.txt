<current_work>
The Solana Gaming Platform is a multi-game dApp integrated with the Solana blockchain and Phantom Wallet. Currently, it features three playable games: Multi-hand Blackjack, Jacks or Better Video Poker, and the SolanaBust crash game.

All games integrate with the Phantom Wallet for user authentication and transaction initiation. Wagers are processed with a 4% developer fee, which is successfully deducted from the player's wallet and sent to the developer's wallet (). The game flow was adjusted so that the full wager amount is deducted upfront upon starting a game.

Player statistics, including win/loss tracking and game history, are managed by the backend (FastAPI + MongoDB). A leaderboard system is also in place, ranking top players by net profit. The frontend is built with React and Tailwind CSS, providing a responsive UI. The SolanaBust game includes a real-time multiplier and an auto-cash-out feature.

**Current Nuances and Known Issues:**
1.  **Payout System (Critical):** While wagers and developer fees are handled on-chain, actual SOL/USDC payouts to winners are currently only simulated via alerts; real transfers from the designated house wallet () are not yet implemented.
2.  **Wallet Balance Display:** Although transactions deduct funds, the frontend balance display does not automatically refresh to show the full wager deduction post-transaction, requiring manual refresh. There have been persistent issues with Phantom wallet popup *displaying* only gas fees, even when console logs confirm correct lamport calculations for the wager amount.
3.  **SolanaBust Stability:** The SolanaBust crash game and its integration (particularly the chat system) are still incomplete or experiencing runtime errors (e.g., ) and syntax errors preventing full compilation and stable operation of recently added features.
4.  **Real-time Features:** The real-time chat and full multiplayer synchronization (e.g., live player list, synchronized crash points) primarily rely on frontend simulation, with the WebSocket backend not fully implemented for actual communication and synchronization.
</current_work>
